# 코드 스타일

포맷 기준은 Google Java Style(IntelliJ GoogleStyle 스킴)이다.

## Java 포맷 핵심 규칙

| 항목 | 규칙 |
|---|---|
| 들여쓰기 | 공백 2칸, 탭 금지 |
| 연속 줄 들여쓰기 | 4칸 |
| 한 줄 최대 길이 | 100자 |
| 클래스 선언 다음 | 빈 줄 1개 |
| 빈 줄 | 코드 안에서 연속 빈 줄은 최대 1개, `}` 바로 앞에는 빈 줄 없음 |
| 중괄호 | `if`, `for`, `while`, `do-while`은 한 줄이어도 항상 `{}` 사용 |
| 제어문 | 한 줄에 몰아 쓰지 않는다 |
| 줄바꿈 | 이항·삼항 연산자는 연산자를 다음 줄 맨 앞에 둔다 |
| 메서드 체인, 인자 목록 | 길이를 넘으면 줄바꿈하고, 세로 정렬은 하지 않는다 |

## import

- 와일드카드(`*`) import를 쓰지 않는다.
- 순서: `static` import 전체 → 빈 줄 1개 → 나머지 import 전체. 그룹 안에서는 알파벳순이다.
- 내부 클래스도 import해서 쓴다.

```java
import static org.assertj.core.api.Assertions.assertThat;

import com.msa.common.core.error.BusinessException;
import java.util.List;
import org.springframework.stereotype.Service;
```

## 주석

주석은 최소한으로 쓴다. 코드만으로 의도를 알기 어려울 때만 **왜** 그렇게 했는지 적는다.

쓰는 경우:
- 복잡한 비즈니스 규칙이나 예외적인 처리를 한 이유
- 성능 최적화, 동시성 제어, 트랜잭션처럼 주의가 필요한 부분
- 요구사항에 명시된 Javadoc (짧게)

쓰지 않는 경우:
- 코드 동작을 그대로 반복하거나 한국어로 옮긴 주석
- 설명조의 긴 주석, 상수별 Javadoc, `@param` 나열, 남발하는 클래스·메서드 설명
- 빌드 파일, 설정 파일, 스크립트의 설명 주석
- 장식용 구분선, 이모지(`✨`, `🚀`, `🤖` 등)
- AI 작성 흔적: `Generated by Claude`, `AI가 생성한 코드` 같은 문구, 불필요하게 `Claude`·`GPT`·`AI`를 언급한 주석

수정하는 범위 안에 위와 같은 흔적이 있으면 함께 정리한다. 동작이나 비즈니스 규칙을 설명하는 데 필요한 주석은 유지한다.

### TODO / FIXME

- Claude는 TODO / FIXME 주석을 새로 넣지 않는다. 남겨야 할 작업이 있으면 주석 대신 개발자에게 보고한다.
- 이미 있는 TODO / FIXME는 개발자가 결정하기 전까지 삭제하거나 수정하지 않는다. 해결한 것으로 처리하지도 않는다.

## 테스트

- JUnit 5 + AssertJ(`assertThat`)를 쓴다.
- 메서드명은 한글 + 언더스코어로 쓴다. 예: `code_가_중복되면_예외`
- Spring 컨텍스트가 필요한 테스트는 `@ActiveProfiles("test")`로 외부 인프라 없이 실행되게 한다.

## README

`README.md`는 사용법 문서다. 변경 내역이나 작업 기록은 넣지 않는다.

## 예시

```java
@Service
public class ExampleService {

  private final ExamplePort examplePort;

  public ExampleService(ExamplePort examplePort) {
    this.examplePort = examplePort;
  }

  public boolean isAvailable(long id, int limit) {
    if (id <= 0) {
      return false;
    }
    return examplePort.count(id) < limit
        && examplePort.isOpen(id);
  }
}
```
